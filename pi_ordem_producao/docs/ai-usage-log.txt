O que o módulo faz
Uma Ordem de Produção (OP) diz à fábrica O QUE produzir, QUANTO, EM QUAL
máquina e ENTRE QUAIS datas. O módulo permite cadastrar OPs, ver a lista,
mudar o status, editar e excluir.

HTML (estrutura)
A página usa tags com significado: <header> (topo com o nome do sistema),
<nav> (links), <main> (conteúdo principal), <section> (formulário e lista),
<article> (cada card de OP) e <footer> (rodapé). Isso ajuda leitores de tela
e buscadores a entender a página. Cada campo tem um <label for="..."> ligado
ao id do campo: clicar no texto foca o campo, e o leitor de tela lê o nome.

CSS (aparência)
- box-sizing: border-box faz o padding e a borda ficarem DENTRO da largura,
  então width: 100% nunca passa da tela.
- As cores ficam em variáveis (:root), e é só trocar num lugar.
- Flexbox organiza coisas em UMA direção (linha do menu, fileira de botões).
- Grid organiza em DUAS direções (linhas e colunas do formulário e dos cards).
- Mobile-first: o CSS básico é para o celular (320px). As @media (min-width)
  acrescentam colunas quando a tela fica larga o bastante. Os pontos de
  quebra (560, 700, 900 e 1040px) foram escolhidos pela largura mínima que
  um campo de data ou um card precisa para não ficar espremido.

JavaScript (comportamento)
- DOM: o script pega os elementos com getElementById e cria os cards com
  innerHTML.
- Eventos: addEventListener("submit") no formulário e um único
  addEventListener("click") na lista (delegação de eventos): o clique de
  qualquer botão "sobe" até a lista, e o script vê qual botão foi.
- Validação: antes de salvar, validar() confere cada campo. Se houver erro,
  nada é gravado e as mensagens aparecem na página.
- localStorage: guarda só texto. JSON.stringify transforma a lista em texto
  para salvar; JSON.parse faz o caminho de volta. Tudo dentro de try/catch
  para a página não quebrar se o dado estiver corrompido.
- Segurança: escaparHtml troca < > & " ' por códigos, então um texto como
  <img onerror=...> aparece escrito em vez de virar código (XSS).
- Regras de status: o objeto TRANSICOES diz para onde cada status pode ir.
  A tela só desenha os botões permitidos, e atualizarStatus() confere de
  novo antes de gravar.
